# Модели и инференс

## Планирование по брифу: Qwen3.5-9B

| Поле | Значение |
|---|---|
| Модель | [Qwen/Qwen3.5-9B](https://huggingface.co/Qwen/Qwen3.5-9B), ревизия `c2022362` |
| Лицензия, размер | Apache 2.0, 9 653 104 368 параметров (лимит ТЗ — 35B) |
| Веса | [unsloth/Qwen3.5-9B-GGUF](https://huggingface.co/unsloth/Qwen3.5-9B-GGUF), `Qwen3.5-9B-Q4_K_M.gguf`, ревизия `3885219b`, 5,68 ГБ |
| Сервер | llama.cpp b11053 (`1af554f8`), `--ctx-size 16384 --parallel 4 --jinja` |
| Режим мышления | выключен запросом: `INFERENCE_EXTRA_BODY={"chat_template_kwargs":{"enable_thinking":false}}` |
| Требования | GPU 8 ГБ (`--n-gpu-layers 99`) или CPU и ~8 ГБ RAM (`--n-gpu-layers 0`) |

Все параметры и SHA-256 — в [deploy/llama/qwen3.5-9b.json](deploy/llama/qwen3.5-9b.json);
`python deploy/llama/setup_local.py` скачивает и проверяет веса и сервер llama.cpp.
Модель строит структуру колоды и пишет текст слайдов (`slide_agent/brief.py`).
Ответы ограничены JSON-схемой, поэтому модель не может вернуть другое число
слайдов или неизвестный тип схемы. Для топ-10 ТЗ требует инференс VK с
Qwen3.8-27B: клиент совместим с любым OpenAI-совместимым сервером (vLLM
поддерживает те же `response_format` и `chat_template_kwargs`), меняются только
`INFERENCE_BASE_URL` и `INFERENCE_MODEL`.

Замеры: на RTX 2070 SUPER структура и текст 12 слайдов занимают 33–38 с,
колода с экспортом — около 1–1,5 минуты. На CPU (i9-10920X, 12 ядер) та же
колода — 722 с, генерация 5,8–6,6 токена/с на 4–12 потоках: для лимита ТЗ в
5 минут на процессоре 9B недостаточно. Подробно —
[reports/brief-llm-2026-09-23](reports/brief-llm-2026-09-23/README.md).

## Подключение модели

Клиент `slide_agent/llm.py` поддерживает совместимый HTTP `/chat/completions`.
Конфигурация задаётся переменными окружения:

```powershell
$env:INFERENCE_BASE_URL="https://your-inference-host/v1"
$env:INFERENCE_MODEL="your-served-model-id"
$env:INFERENCE_API_KEY="your-token"
$env:INFERENCE_VISION="1"
```

Ключ не хранится в исходниках и отчётах. Текстовая модель планирует структуру и
визуализации в JSON. При включённом vision анализатор может передать до четырёх
превью для качественных рекомендаций. Цвета, шрифты и координаты остаются
основанными на OOXML. Ошибка модели приводит к явно обозначенному `fallback`.

По предоставленному ТЗ допускаются модели с открытыми весами и лицензией
Apache 2.0/MIT, до 35B; для дополнительного задания text-to-image указан предел
20B. Для финалистов требуется организаторский inference. Соответствие модели
подтверждает её model card: для Qwen3.5-9B URL, лицензия, ревизия, число
параметров, квантование и конфигурация сервера приведены в таблице выше.

Основной pipeline работает без обучения: шаблоны разбираются при загрузке, и
новый стиль не требует дообучения модели. Разбор OOXML, сборка и экспорт работают
на CPU.

Пиктограммы, схемы и сопоставление картинок работают без моделей: это
детерминированные правила и словари (`slide_agent/assets`).

Генерация изображений (задача со звёздочкой) подключается отдельно через
OpenAI-совместимый `/images/generations`: `IMAGE_BASE_URL`, `IMAGE_API_KEY`,
`IMAGE_MODEL`, `IMAGE_SIZE` (1024x768), `IMAGE_TIMEOUT`, `IMAGE_MAX_PER_DECK` (3),
`IMAGE_AUTO` (0 — только слайды, где планировщик запросил картинку). По ТЗ нужна
модель text-to-image до 20B с открытыми весами Apache 2.0/MIT, например
[FLUX.1-schnell](https://huggingface.co/black-forest-labs/FLUX.1-schnell)
(12B, Apache 2.0). Клиент проверен только на mock-сервере; реальная модель не
запускалась. Сгенерированный файл записывается в план с SHA-256 промпта.

Опциональный текстовый аудит `INFERENCE_CONTEXT_AUDIT=1` проверяет общий план на
неподтверждённые утверждения, повтор смысла и заголовки без вывода. Он не видит
рендеры.

## Визуальный аудит: та же Qwen3.5-9B с проектором изображений

Qwen3.5-9B мультимодальна: чтобы она видела картинки, llama.cpp загружает
проектор [`mmproj-F16.gguf`](https://huggingface.co/unsloth/Qwen3.5-9B-GGUF)
(0,92 ГБ, та же ревизия `3885219b`, SHA-256 в
[deploy/llama/qwen3.5-9b.json](deploy/llama/qwen3.5-9b.json)).
`python deploy/llama/setup_local.py` скачивает его вместе с весами,
`deploy/llama/start-llama.ps1` подключает, если файл есть. На RTX 2070 SUPER
8 ГБ проектор помещается рядом с моделью (занято 7,8 ГБ): один слайд — около
6 с разбора картинки, колода из 10 слайдов — 45–100 с при трёх параллельных
запросах. С проектором в оперативной памяти (`-ProjectorOnCpu`) — около 33 с
на слайд.

Аудит включается переменными `INFERENCE_VISION=1` и `INFERENCE_RENDER_AUDIT=1`.
После экспорта LibreOffice модель получает PNG каждого итогового слайда, его
роль и бриф и отвечает «да / нет / неприменимо» на вопросы «Валидации контента»
Приложения 1 ТЗ (1–8 и 10), а также называет видимые дефекты: обрезанный
текст, наложения, нечитаемые графики, неуместные картинки. Инструкция —
[`prompts/vision-audit-v1.txt`](slide_agent/prompts/vision-audit-v1.txt).
Ответы и замечания — подсказки редактору: они не меняют структурный
`QA.score`. Заполненность слайда и язык слов модель не оценивает: при проверке
на заведомо плохих колодах она то пропускала их, то отмечала пустоту и логотип
почти на каждом слайде, а детерминированные проверки меряют это точно.
Результат прогона по девяти колодам — в
[reports/vision-audit-2026-09-28](reports/vision-audit-2026-09-28/README.md).
Время аудита не входит в замер 3 × 3: там он выключен, чтобы уложиться в 300 с
на шаблон. Использование закрытых моделей по
умолчанию не заложено; клиент не проверяет лицензию модели автоматически, поэтому
её нужно зафиксировать перед конкурсным запуском.
