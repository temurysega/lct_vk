# Краткий бриф → 12 слайдов на Qwen3.5-9B — 23 сентября 2026

Первый прогон всего конвейера с реальной открытой моделью: из брифа в 8
предложений ([examples/brief_feature.md](../../examples/brief_feature.md),
назначение «фича», бриф синтетический) модель строит структуру колоды и пишет
текст слайдов, дальше — вёрстка по шаблону, аудит и экспорт PPTX/PDF/HTML.

## Установка

| | |
|---|---|
| Модель | Qwen3.5-9B, GGUF Q4_K_M, 5,68 ГБ, Apache 2.0 — [профиль и SHA-256](../../deploy/llama/qwen3.5-9b.json) |
| Сервер | llama.cpp b11053, 4 слота × 4096 токенов, мышление выключено запросом |
| GPU | RTX 2070 SUPER 8 ГБ, вся модель в видеопамяти (6,8 ГБ занято) |
| CPU | Intel Core i9-10920X, 12 ядер, 16 ГБ RAM, `--n-gpu-layers 0` |

```powershell
powershell -File deploy/llama/start-llama.ps1          # GPU; -Device cpu для процессора
python examples/run_dataset.py --config examples/brief_demo.json
python examples/contact_sheet.py slide-workspace/brief-qwen3.5-9b <папка для PNG>
```

## Результат на GPU: 3 шаблона × 3 варианта

| Шаблон | Структура | Текст 12 слайдов | Три варианта целиком | QA (balanced / columns / focus) | Экспорт |
|---|---:|---:|---:|---|---|
| VK Tech | 14,4 с | 18,1 с | 108,6 с | 100 / 100 / 100 | PPTX, PDF, HTML |
| VK WorkSpace | 14,7 с | 21,6 с | 98,7 с | 100 / 100 / 100 | PPTX, PDF, HTML |
| VK Education | 15,5 с | 22,7 с | 100,1 с | 100 / 100 / 100 | PPTX, PDF, HTML |

Все 9 колод — ровно 12 слайдов, статус `completed`, варианты различаются
(`diversity=passed`), исходные PPTX не изменились. Весь прогон — 309 с.
Одна колода с моделью, анализом шаблона и экспортом — около 1–1,5 минуты,
лимит ТЗ 5 минут выполняется с запасом. Числа брифа на слайдах переданы
верно, проверка `number_not_in_source` замечаний не дала. Подробности —
[summary.json](summary.json) (включая структуру, которую построила модель).

## Без видеокарты

Тот же файл весов на процессоре ([cpu.json](cpu.json)):

| | 4 потока | 12 потоков |
|---|---:|---:|
| Обработка промпта (llama-bench pp512) | 25 ток/с | 54 ток/с |
| Генерация (tg128) | 5,8 ток/с | 6,6 ток/с |
| Колода 12 слайдов с экспортом | ≈ 12–15 мин (оценка) | **722 с** (замер), QA 100 |

Генерация упирается в пропускную способность памяти, поэтому число ядер почти
не помогает. На CPU 9B не укладывается в 5 минут на колоду. Варианты: GPU
(свой или организаторский инференс, обязательный для топ-10), модель меньше
(Qwen3.5-4B, примерно вдвое быстрее) или MoE Qwen3.6-35B-A3B (3B активных
параметров, быстрее на CPU, но ≈ 22 ГБ RAM и 35,95B параметров — на грани
лимита ТЗ). Для сервера без GPU подготовлен [compose.llm-cpu.yaml](../../compose.llm-cpu.yaml).

## Что исправлено по ходу прогона

Первые прогоны на Qwen2.5-1.5B и на 9B нашли проблемы, которые не зависят от модели:

| Наблюдение | Исправление |
|---|---|
| Слабая модель заменяла заголовки слайдов названием колоды | Заголовок фиксируется на этапе структуры |
| Одинаковые заголовки и цели в структуре | Структура один раз запрашивается повторно со списком повторов |
| Ограничение длины в грамматике обрезало пункт посреди слова | Лимиты в схеме — только страховка; длинный текст возвращается модели на сокращение |
| Схема «цикл» из 6 длинных пунктов переполняла зону | Не больше 5 элементов, подпись до 5 слов, пояснение до 16 |
| Пустые элементы схемы → слайд с одним заголовком | Такой ответ запрашивается повторно, иначе текст схемы или цель слайда становятся пунктами; новая проверка `title_only` |
| Карточки метрик и таймлайн попадали в мелкие зоны или на декор макета | В режиме брифа только схемы собственного движка и таблицы; при выборе макета теперь учитывается текст карточек, таблиц и таймлайнов (старый недочёт для всех режимов) |
| Запасной подзаголовок финального слайда ложился поверх пунктов | Composer переносит его под заголовок или не добавляет |
| Английские слова и «Сolution» у 1.5B | Проверки `mixed_script_word`, `language_mix` |
| Модель 9B написала «33%» вместо «трети» | Поймано проверкой `number_not_in_source` |

## Ограничения

- Один синтетический бриф и одно назначение. Разные запуски модели дают разные
  структуры: в одном прогоне больше схем, в другом больше пунктов.
- QA = 100 не значит идеальный слайд. Остались дефекты шаблонов, которые
  детерминированный аудит не видит: в VK WorkSpace синий текст на тёмно-серых
  карточках, пустые рамки и декоративные «таблетки» из примеров макета; в
  VK Education часть текста мелкая.
- Смысловой аудит (Приложение 1, «Валидация контента») не реализован. Пример:
  фраза «сократим время с 30 минут до нескольких секунд» в колоде VK Education
  не подтверждена брифом, но чисел вне брифа в ней нет, поэтому она не помечена.
- Качество оценивал один проверяющий по контактным листам LibreOffice.
