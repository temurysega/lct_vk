# Проверка CPU-профиля

Подготовлен автономный профиль VPS: 4 ГБ ОЗУ, 4 CPU, без GPU.
Colab используется для обучения Qwen2.5-1.5B-Instruct и экспорта базы Q4_K_M
и отдельного LoRA GGUF. Старый адаптер Qwen 7B не переносится на новую базу.
Готовый комплект данных: `../gdrive/lct_cpu`, 297 обучающих строк / 88 групп,
27 проверочных строк. Ноутбук: `examples/BrandDeck_CPU_Training_Export.ipynb`.

Проверено локально 19.09.2026:

- `pytest`: **61 passed, 1 skipped**. Один warning о Starlette/httpx.
- Ruff, `compileall`, `git diff --check`; Compose YAML разобран парсером.
- Реальный Windows CPU runtime llama.cpp **b11053**, закреплённый исходник
  `1af554f8fc78ba029665a47b839484d9763e2a75`.
- Официальная базовая `Qwen2.5-1.5B-Instruct-GGUF`, Q4_K_M,
  файл 1 117 320 736 байт. 4 потока, контекст 4096, один слот,
  GPU выключен, RAM-кэш выключен.
- Три первых примера validation: 3/3 допустимых JSON, 0/3 совпадений со слабой
  меткой (эвристика 1/3). Это проверка исполнения, не оценка качества модели.
- Пробный план из трёх слайдов: корректный JSON и требуемое число объектов.
- Пик RSS процесса модели: **1 812 090 880 байт**, около **1,69 ГиБ**.
  Это память базовой модели на данном компьютере, не всего VPS и не будущего LoRA.
- Проверены изоляция LoRA по запросам, ограничение контекста без обрезания
  исходника, отказ при неполном ответе, несовместимость старого адаптера,
  контрольные суммы переносимого комплекта и синтаксис ячеек notebook.

Исходные измерения локально: `slide-workspace/cpu-base-final/report.json` и
`report.server.log`. Повторение: `python -m training.check_gguf --help`.
Проверка полного восстановления Trainer отдельно описана в
[отчёте чекпоинтов](../drive-training-2026-09-19/README.md).

Новое обучение на A100, конвертация именно дообученного 1.5B-адаптера,
сборка Docker и запуск на целевом VPS ещё не выполнялись: доступа к этим средам
нет. Ноутбук проверяет экспортированный комплект на CPU перед публикацией.
Скорость на Intel E5, память всего приложения и визуальное качество PPTX
нужно проверить после обучения и развёртывания. Веса и локальные датасеты
не включены в Git; они передаются через Google Drive и `cpu_bundle.zip`.
