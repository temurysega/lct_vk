# Проблемы и воспроизведение

Дата: 27.09.2026. Версия: `main`, `4330625b355f1516cf00c3e9b94437b074ca6c49`.
P0/P1/P2 ниже — приоритет исправления по мнению аудитора, **не официальные веса или баллы**. Полный запуск и переменные окружения — в [VALIDATION.md](VALIDATION.md).

## P0-1. Адаптация к новому шаблону не обеспечивает пригодную композицию

**Требование:** «Решение не должно быть заточено под три предоставленных шаблона»; на защите используется неизвестный шаблон — [ТЗ, PDF с. 3](sources/official-task.pdf#page=3). Критерии 2, 3, 4, PDF с. 5.

**Воспроизведение:** запустить `scripts/api_audit.py` с временным LibreOffice; открыть `with-renderer/artifacts/unseen-brutalism/balanced`. Вход: реальный `pptmaster-brutalism_field_guide.pptx`, полный текст `sources/audit-content.md`, 10 слайдов, две картинки, `mode=source`, `offline=true`.

**Результат:** после структурных повторов, рендера и повторной сборки — 25/26/25 замечаний по трём вариантам. Все восемь содержательных слайдов занимают только 19,2–22,6% площади по собственной метрике проекта. Заголовки пересекает линия шаблона; текст и фотография сведены к узкой полосе, фотография теряет полезную часть кадра. Варианты balanced/columns различаются заметно лишь на слайде 3, balanced/focus — на слайде 7. Порог «два изменённых слайда» — внутренняя эвристика проекта, не отдельное число из ТЗ.

**Доказательства:** [манифест](with-renderer/artifacts/unseen-brutalism/balanced/manifest.json), [полный слайд 3](with-renderer/artifacts/unseen-brutalism/balanced/libreoffice-slide-03.png), [обзор](with-renderer/artifacts/unseen-brutalism/balanced/libreoffice-contact-sheet.jpg), [сравнение вариантов](evidence/rendered-diversity.json). Дефект общей композиции виден и в независимом [PowerPoint-рендере исходного прогона](artifacts/unseen-brutalism/balanced/powerpoint-contact-sheet.jpg).

**Граница вывода:** исходный внешний шаблон сам не идеален при рендере в этом окружении: переносы крупных номеров и часть пересечений уже есть в [исходнике](sources/unseen-brutalism/source-slide-05.png). Они не записаны как новые дефекты BrandDeck. Новые узкие зоны, потеря иерархии и почти одинаковые варианты подтверждены сравнением. Нельзя по этому одному файлу заключать, что не работает любой внешний шаблон.

**Место:** `analyzer.py:878` классифицирует exemplar-зоны; в `analysis-pattern_catalog.json` крупный номер страницы принят за `title`, а настоящие заголовки — за `body`. Затем `planner.py:455` и `composer.py:2525` выбирают/заполняют эти зоны; `service.py:482` повторяет раскладку после проверки заполненности.

**Минимальное исправление:** отделять навигационные номера/колонтитулы от заголовков и содержательных зон; проверять минимальную полезную ширину под текст/визуал; после неудачного ремонта выбирать реально иную пригодную композицию. Проверить исправление на нескольких новых шаблонах, включая нешаблонные exemplar-слайды.

**Второй независимый пример — Onocom.** В варианте `focus`, слайд 9, русский текст расположен вертикально: выбран `/ppt/slideLayouts/slideLayout9.xml`, placeholder idx=1 наследует `bodyPr vert=eaVert`. У generated text frame нет override направления. Это подтверждено [OOXML](evidence/onocom-vertical-text.json) и [реальным LibreOffice PNG](additional-unseen/artifacts/unseen-onocom/focus/libreoffice-slide-09.png). В отчёте этой колоды только overfilled на слайдах 2 и 6; слайд 9 не отмечен. На слайде 4 также видно [выступание текста из карточек](additional-unseen/artifacts/unseen-onocom/balanced/libreoffice-slide-04.png). Font `游ゴシック` даёт разреженное отображение; влияние конкретного Office/font substitution на интервалы не отделено, PowerPoint для этого файла не проверен. Вертикальное направление при этом присутствует в самом layout XML.

Воспроизведение второго случая: API script с `AUDIT_TEMPLATE_FILTER=unseen-onocom`, 10 слайдов, source offline, 3 variants; открыть `focus`, слайд 9. Исходный шаблон имеет 2 почти пустых слайда, типы макетов содержатся в masters/layouts; анализ только видимых исходных слайдов не раскрывает этот риск. При исправлении учитывать ориентацию и язык placeholder до назначения паттерна, а затем проверять фактический рендер.

## P0-2. Установочный пакет не содержит исполняемый парсер шаблонов

**Требование:** воспроизводимый сетап и запуск конфигом — [ТЗ, PDF с. 5](sources/official-task.pdf#page=5); критерий 2.

**Воспроизведение:** из `git archive HEAD` собрать wheel в отдельной временной среде; распаковать его и вызвать `slide_agent.analyzer._load_extractor()` с импортом именно из установленного пакета. Команды приведены в VALIDATION.

**Результат:** `FileNotFoundError: Template extractor is missing: …/wheel-site/shared/scripts/extract_template.py`. `shared/` не включён в package discovery/data. Сборка wheel успешна, но анализ невозможен. В wheel из чистого checkout также нет `frontend/dist/index.html`, поскольку предварительная сборка frontend не выполнена; это отдельное требование порядка сборки.

**Доказательства:** [wheel-smoke.json](evidence/wheel-smoke.json), [сборка wheel](evidence/wheel-build-isolated.log); `pyproject.toml:28`, `slide_agent/utils.py:13`, `slide_agent/analyzer.py:32`.

**Влияние:** успешный запуск из editable checkout не подтверждает установку на машине эксперта. Dockerfile использует `pip install ".[api,export]"` и console entrypoint (`Dockerfile:20`, `Dockerfile:24`), поэтому такая упаковка представляет риск и для контейнера. **Сам Docker не запускался: daemon недоступен**; контейнерный отказ здесь — вывод из воспроизведённого дефекта wheel, не результат Docker-теста.

**Минимальное исправление:** включить extractor в пакет и получать его через package resources; собирать frontend перед wheel; добавить один smoke-test установки пакета вне checkout с анализом реального PPTX.

## P0-3. Обязательная генерация по брифу не готова к живому показу в текущем окружении

**Требование:** структура и текст по краткому брифу и назначению — [ТЗ, PDF с. 2](sources/official-task.pdf#page=2); живая демонстрация — PDF с. 4–5.

**Воспроизведение:** POST `/v1/presentations/generate` с `mode=brief`, 10 слайдами и кратким брифом либо ввод короткого текста в свежем UI без настроенного inference.

**Результат:** API возвращает 400 с явным требованием модели; автоматический offline-режим UI возвращает `Not enough source material for the requested slide count; request fewer slides`. Это не доказательство дефекта работающей модели: endpoint/model не настроены, ключи отсутствуют, локальный inference не запущен.

**Доказательства:** [API, событие `brief without model`](evidence/api-events.json), [браузер](evidence/browser-current.json), [экран](artifacts/browser-current/brief-without-model.png); `brief.py:80`, `planner.py:296`, `frontend/src/hooks/useStudio.ts:166`.

**Минимальное действие:** подключить разрешённый inference и выполнить новый приёмочный прогон на текущем коммите: краткий бриф → 10–15 слайдов → все три варианта → рендер → смысловая сверка → время до 300 с на колоду. Для топ-10 нужен именно VK inference. Никакого восстановления обучения малой модели для этого ТЗ не требует.

## P1-1. Диаграммы нативны, но плохо читаются; часть проверок их пропускает

**Требование:** генерация графиков/диаграмм и качество композиции/читаемости — [ТЗ, PDF с. 2, 5](sources/official-task.pdf#page=2), ориентиры приложения — с. 6–7.

**Воспроизведение:** `scripts/component_visuals.py`, затем компонентный прогон через `_generate_from_plan` из VALIDATION. Реальный шаблон VK Education, две категории 60/90, `pie_chart`; план задаёт аудитор, **LLM не используется**.

**Результат:** числа и легенда круговой диаграммы переносятся почти по символам, сама диаграмма мала; появляется английский заголовок `Values`. После полного сервиса с QA/рендером/повторами проблема остаётся. Начальный структурный QA — `passed`, без замечаний. Полный сервис отмечает малую заполненность, но не повреждённые подписи или язык диаграммы.

**Доказательства:** [реальный рендер после полного сервиса](artifacts/component-service/vk-education/libreoffice-slide-03.png), [манифест](artifacts/component-service/vk-education/manifest.json), [начальный QA](artifacts/component-visuals/vk-education/qa.json). Контрольные данные и план сохранены; это проверка компонента сборки, не утверждение, что модель сама выбрала такую диаграмму.

**Место:** `composer.py:923`, `composer.py:971`; созданные графики называются `Chart 888`, тогда как `layout_geometry.py:151` распознаёт сгенерированные объекты по `BrandDeck`. `style_audit.py:85` обходит только такие объекты; `render_audit.py:135` также опирается на этот признак. Значение 6,1% заполненности этого слайда нельзя считать точной площадью графика: график исключён из маски. Текст графиков не охвачен языковым QA так же, как обычные текстовые рамки.

**Минимальное исправление:** включить диаграммы в единый учёт сгенерированных объектов, нормализовать plot area/легенду/подписи и язык; проверять их на реальном рендере, сохранив редактируемые chart parts и workbook.

## P1-2. Выборочное исправление создаёт версию, но не устраняет выбранный дефект

**Требование:** пользователь выбирает исправления во встроенном аудите — [ТЗ, PDF с. 3](sources/official-task.pdf#page=3); критерии 3, 4.

**Воспроизведение:** свежий UI, unseen-brutalism, выбрать первое `decor_overlap` на слайде 1 и нажать «Исправить выбранные».

**Результат:** POST `/repair` → 200, новая `revision.parent_id`, изменён только план слайда 1; `decor_overlap` на нём остаётся. При наличии рендера: 25 замечаний до и после. Без LibreOffice: `failed` родителя превращается в `completed` новой версии, потому что экспорт перестаёт запрашиваться (`failed` → `skipped`). Исходник сохранён, несвязанные слайды не перепланированы — эта часть работает.

**Доказательства:** [сравнение с рендером](with-renderer/evidence/repair-comparison.json), [без рендера](evidence/repair-comparison.json), [браузер](with-renderer/evidence/browser-current.json). `service.py:805`, особенно передача `export_formats` в конце `repair_presentation`.

**Минимальное исправление:** сохранять запрошенные форматы независимо от успеха предыдущего экспорта; сравнивать выбранные нарушения до/после; сообщать «не устранено», если новый макет не помог, и предлагать другой способ исправления.

## P1-3. Комплект запуска требует явной подготовки рендера, шрифтов и свежего UI

**Воспроизведение:** обычный `uvicorn backend.main:app` из предоставленной рабочей папки. До аудита: LibreOffice отсутствует; `frontend/dist` собран раньше текущих исходников.

**Результат:** PPTX доступны, PDF/HTML/превью — 404, все четыре задания с `export_all=true` получают `failed`. В старом UI нет `#imageFiles` и `#purpose`; в свежей временной сборке оба поля есть. С временным LibreOffice экспорт полностью заработал. Шрифт `Play` остаётся в PPTX, но в PDF текущего LibreOffice заменён на `ArialUnicodeMS`; `Consolas` во внешнем шаблоне — на `DejaVuSansMono`. Побайтовая/каноническая проверка тем, masters и layouts подтверждает сохранность их XML, но не наличие системных шрифтов.

**Доказательства:** [baseline](evidence/baseline.json), [API до подготовки](evidence/api-summary.json), [API с рендером](with-renderer/evidence/api-summary.json), [различия UI](evidence/frontend-features.json), [шрифты PDF](evidence/design-and-pdf-comparison.json).

**Влияние:** критерии 2 и 4, экспорт/визуальный аудит на живом показе. Это смесь состояния локальной установки и требований к воспроизводимому старту; отсутствие полей не приписывается актуальным TSX-исходникам.

**Минимальное действие:** собрать frontend, установить/подключить renderer и нужные шрифты в демонстрационном окружении, запускать preflight с реальной проверкой доступности экспортера. В аудите всё подключалось только во временной папке; продукт не исправлялся.

## P1-4. Объявленные форматы контент-пакета недоступны в базовой конфигурации

**Воспроизведение:** загрузить корректный PDF как `content_file`, а не как шаблон. POST jobs принимается, job завершается ошибкой об optional `documents` dependencies.

**Доказательства:** [api-negative.json](evidence/api-negative.json); `planner.py:61`, `pyproject.toml:20`, `Dockerfile:20`. UI предлагает PDF/DOCX/XLSX (`frontend/src/pages/Studio.tsx:219`). PDF-шаблоны и PDF-материалы идут разными путями — успешный разбор первого не доказывает поддержку второго.

**Влияние:** импорт контент-пакетов, критерии 2–4. Реальный официальный контент-пакет в предоставленной папке не обнаружен; неизвестно, затронет ли именно его формат.

**Минимальное исправление:** включить необходимые конвертеры в выбранный вариант поставки либо показывать только доступные форматы с явной диагностикой до постановки задания.

## Ограничения, которые не следует выдавать за найденные сбои

- Нет live LLM/VLM/text-to-image/VK inference. Mock-тесты не подтверждают их качество, скорость и совместимость с текущим сервисом организатора.
- SmartArt-подобные схемы состоят из редактируемых групп фигур; OOXML SmartArt parts отсутствуют. Буквальное требование «элементов SmartArt» выполнено не полностью либо требует подтверждения допустимой трактовки организатором. Это не растровые слайды.
- Доступна проверка Chrome на macOS. Firefox/WebKit из установленного Playwright не стартовали из-за отсутствующих подходящих бинарников; Safari, Яндекс, предыдущие версии и Windows не проверены.
- Полный рендер PowerPoint удалось получить для двух baseline-колод. Дальнейшая автоматизация блокировалась диалогом приложения; это не доказательство повреждения остальных PPTX. Остальные реальные рендеры сделаны LibreOffice, схематика за них не выдавалась.
- Отсутствие обучения малой модели не нарушает ТЗ. Не рекомендуется тратить время на его восстановление ради этой приёмки.
