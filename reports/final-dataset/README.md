# Проверяемые результаты прогона 3 × 3

[`evidence.json`](evidence.json) — компактная выгрузка исходного
`slide-workspace/final-2026-09-26j/dataset_report.json`. Здесь нет абсолютных
путей, адреса API, ключей и ответов модели. Для каждого шаблона и варианта
указаны время, результат машинных проверок, число слайдов и изображений, SHA-256
опубликованных PPTX/PDF. Хэши девяти PDF совпали с экспортом исходного прогона.
PPTX в `deliverables/` прошли дополнительное сжатие и поэтому имеют свой хэш.

Это **исторический прогон 26.09.2026**. Его `source_digest_at_run` равен
`0fb0a9445fec0f9b74432ada0ad51b632aefe03bd8e75fb87f8cf5b16e954d82`.
Он не совпадает с текущими исходниками, а отчёт того запуска ещё не записывал
Git revision и хэши использованных изображений. Файлы изображений сейчас есть,
но их байты на момент старого запуска отдельно не зафиксированы. Поэтому точное
повторение этих девяти колод из одного клона Git пока не доказано. Повторный запуск должен сохранить новый `dataset_report.json`
и обновить эту выгрузку после того, как код перестанет меняться. Новый runner
записывает ревизию Git, состояние исходников, UTC-время и хэши входов до и после
прогона; `--verify` сверяет их с содержимым клона.

## Проверить файлы и запустить снова

Три исходных PPTX входят в выданный датасет организаторов, но не в этот Git
репозиторий. Поместите папку `task+data/Датасет` рядом с каталогом `lct_vk`
или измените `templates` в копии `examples/brief_demo.json`. Проверка
`--verify` сравнивает их SHA-256 с зафиксированными значениями:

| Файл | SHA-256 |
|---|---|
| `VK Tech шаблон.pptx` | `cbbe3aa6a21d23cebc4d1383b93dd07a9cea460d683de1903567b616c839485d` |
| `VK_WorkSpace_Клиентская_конференция_Шаблон_03.pptx` | `1b8883114486c69dff706e9c4fd9382727c4506c2cfa3ec34f86987f1e852f2f` |
| `Шаблон презентации VK Education.pptx` | `9ef2323ed5f49f464aee5ae7065f1f57bb92c8be3a635be507d59819e285cfe0` |

Модель и сервер описаны в [`deploy/llama/qwen3.5-9b.json`](../../deploy/llama/qwen3.5-9b.json).
Для измеренного запуска использовались Windows, RTX 2070 SUPER 8 ГБ,
Qwen3.5-9B Q4_K_M и llama.cpp b11053. Веса не входят в Git. Установите
Python-зависимости, LibreOffice и шрифты шаблона по [основному README](../../README.md),
затем запустите сервер модели. Из корня репозитория:

```powershell
python examples/export_run_evidence.py --verify
python examples/run_dataset.py --config examples/brief_demo.json
python examples/export_run_evidence.py --report slide-workspace/final-2026-09-26j/dataset_report.json
```

Первая команда на текущей версии ожидаемо сообщает о несовпадении исходников
исторического прогона. Вторая заново строит все девять колод и проверяет пороги
конфига. Третья сохраняет короткий отчёт для Git. Перед обновлением опубликованных
PPTX/PDF выполните `examples/collect_deliverables.py` на новом отчёте, затем
снова экспортируйте evidence, чтобы SHA-256 относились именно к новым файлам.
После нового прогона `--verify` проверит код, входы и все опубликованные файлы.

`QA=100` означает прохождение заданных структурных и рендерных проверок. Поле
`editorial_suggestions` показывает оставшиеся замечания текстового аудита, которые
не влияют на балл QA. Текст, изображения и дизайн нужно отдельно проверить перед
показом. Время зависит от модели, оборудования, нагрузки и числа переписанных
слайдов; повтор не обязан иметь те же секунды и байты.
