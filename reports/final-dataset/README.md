## Проверить файлы и запустить снова

Три исходных PPTX входят в выданный датасет организаторов, но не в этот Git
репозиторий. Поместите папку `task+data/Датасет` рядом с каталогом `lct_vk`
или измените `templates` в копии `examples/brief_demo.json`. Проверка
`--verify` сравнивает их SHA-256 с зафиксированными значениями:

| Файл | SHA-256 |
|---|---|
| `VK Tech шаблон.pptx` | `cbbe3aa6a21d23cebc4d1383b93dd07a9cea460d683de1903567b616c839485d` |
| `VK_WorkSpace_Клиентская_конференция_Шаблон_03.pptx` | `1b8883114486c69dff706e9c4fd9382727c4506c2cfa3ec34f86987f1e852f2f` |
| `Шаблон презентации VK Education.pptx` | `9ef2323ed5f49f464aee5ae7065f1f57bb92c8be3a635be507d59819e285cfe0` |

Модель и сервер описаны в [`deploy/llama/qwen3.5-9b.json`](../../deploy/llama/qwen3.5-9b.json).
Для измеренного запуска использовались Windows, RTX 2070 SUPER 8 ГБ,
Qwen3.5-9B Q4_K_M и llama.cpp b11053. Веса не входят в Git. Установите
Python-зависимости, LibreOffice и шрифты шаблона по [основному README](../../README.md),
затем запустите сервер модели. Из корня репозитория:

```powershell
python deploy/llama/setup_local.py          # один раз: веса и llama.cpp
powershell -File deploy/llama/start-llama.ps1
python examples/rebuild_deliverables.py --check
python examples/rebuild_deliverables.py
```

`--check` только проверяет готовность и ничего не запускает:

- код `slide_agent/`, конфиг, бриф и картинки закоммичены без локальных правок,
  иначе прогон нельзя связать с ревизией;
- в папке `templates` конфига лежат ровно три PPTX организаторов с SHA-256 из
  таблицы выше;
- LibreOffice найден, сервер модели отвечает на `/models`.

Без `--check` команда выполняет пять шагов и останавливается на первой ошибке:

1. та же проверка;
2. `run_dataset.py` строит девять колод в `workspace` конфига. Прежняя папка
   прогона переименовывается в `<workspace>-before-<время UTC>`, поэтому шаблоны
   каждый раз разбираются заново и время сравнимо с опубликованным;
3. `collect_deliverables.py` копирует колоды в `deliverables/`;
4. `export_run_evidence.py` пишет `evidence.json`;
5. `export_run_evidence.py --verify` сверяет всё с клоном.

Если хоть один порог конфига не пройден (QA, картинки, различимость, 300 с на
шаблон), ничего не публикуется. Текст модели меняется от попытки к попытке,
поэтому команду можно просто запустить ещё раз. После успеха она печатает
таблицу для раздела «Результаты» README. Останется обновить цифры в README и в
этом отчёте, закоммитить `deliverables/` и `evidence.json` и поставить тег
версии.

Отдельно `python examples/export_run_evidence.py --verify` проверяет, что клон
совпадает с опубликованным прогоном: код, конфиг, бриф, картинки, шаблоны и
девять колод. Пока колоды не пересобраны на текущей версии, она ожидаемо
сообщает о несовпадении кода и конфига.

Хэши считаются по байтам файлов. Раньше клон на Windows с `core.autocrlf`
хранил код и бриф с CRLF, поэтому опубликованный прогон `f96244b` сверялся
только с такой же копией: на macOS и Linux хэш брифа не совпадал. Теперь
`.gitattributes` закрепляет LF для `slide_agent/`, конфигов и брифов в
`examples/` на любой ОС. Старую Windows-копию `rebuild_deliverables.py` сама
переписывает с LF, если в этих файлах нет локальных правок.

`QA=100` означает прохождение заданных структурных и рендерных проверок. Поле
`editorial_suggestions` показывает оставшиеся замечания текстового аудита, которые
не влияют на балл QA. Текст, изображения и дизайн нужно отдельно проверить перед
показом. Время зависит от модели, оборудования, нагрузки и числа переписанных
слайдов; повтор не обязан иметь те же секунды и байты.
