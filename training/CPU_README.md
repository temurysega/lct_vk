# Colab для обучения, VPS для работы

Цель: автономное приложение на VPS с **4 ГБ ОЗУ, 4 CPU, без GPU**.
Модель — [Qwen2.5-1.5B-Instruct](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct),
квантование Q4_K_M, контекст 4096 токенов, один запрос одновременно.
Colab нужен только для обучения, экспорта и проверки весов. Постоянные внешние API не нужны.

## Подготовка Google Drive

Из корня репозитория:

```bash
python -m training.prepare_drive --profile cpu
```

Готовая папка: `../gdrive/lct_cpu`. Загрузите её целиком в «Мой диск»
аккаунта с A100. Внутри уже лежат три исходных PPTX, извлечённые `data/train.jsonl`
и `data/validation.jsonl`, контрольные суммы, скрипты и ноутбук.
PDF с условиями, весь репозиторий и прежний `adapter.zip` загружать не нужно.
Аккаунт Google может отличаться от аккаунта GitHub.

Откройте **`BrandDeck_CPU_Training_Export.ipynb`** в Colab (Файл → Загрузить блокнот),
выберите A100, выполните все ячейки. Исходник ноутбука в репозитории:
`examples/BrandDeck_CPU_Training_Export.ipynb`.
Путь в Colab: `/content/drive/MyDrive/lct_cpu`.
Python 3.12 создаётся через uv, независимо от системного Python Colab.

Старый LoRA для Qwen 7B несовместим с 1.5B. Новый комплект использует отдельную
папку и новые запуски. Обучаются только дополнительные веса выбора макетов;
содержание планирует базовая модель. Данные имеют слабую разметку: исходный
макет из PPTX — целевой кандидат. Это не экспертная оценка дизайна.
WorkSpace выделен целиком для проверки, совпадающие группы исключены.

## Чекпоинты и результат

- `runs/<run_id>/checkpoints/`: две последние проверенные копии полного состояния
  (веса, optimizer, scheduler, RNG, Trainer, SHA-256). Сохранение после первого
  шага, каждых 10 шагов и в конце каждой эпохи.
- `RESUME='auto'`: восстановление после обрыва; завершённый запуск не повторяется.
  После сброса Colab повторите ячейки 1–3 с прежними параметрами.
- `weights/`: исходный PEFT-адаптер, токенизатор, метрики и архив для дальнейшего обучения.
- `exports/latest.json`: путь к последнему готовому `cpu_bundle.zip` и SHA-256.
  Архив включает **базу** `base-q4_k_m.gguf` и **адаптер** `layout-lora-f16.gguf`.

Экспорт выполняет сравнение базы/LoRA/эвристики на CPU уже после квантования,
проверяет загрузку, пиковую память процесса и структуру пробного плана.
LoRA включается через `deployment.env` только при улучшении относительно базы
и эвристики и 100% допустимых ответов на проверке. Иначе приложение использует
эвристику выбора макетов; обученные веса всё равно сохраняются в архиве.
На слабой небольшой выборке это лишь предварительная проверка.

## Запуск на VPS

Нужны Linux x86-64, Docker Engine с Compose v2, Git, Python 3, unzip,
свободный диск для образов и весов (желательно от 12 ГБ).
Скачайте архив из Colab, перенесите на VPS и из корня репозитория выполните:

```bash
mkdir -p models
unzip /path/to/cpu_bundle.zip -d models
python3 deploy/cpu/verify_bundle.py
docker compose -f compose.cpu.yaml up -d --build
docker compose -f compose.cpu.yaml ps
curl http://127.0.0.1:8000/health
```

Должно получиться `models/cpu/base-q4_k_m.gguf` (без лишней вложенной папки).
Архив содержит всю базовую модель: запуск VPS не скачивает веса с Hugging Face.
Первая сборка Docker скачивает системные зависимости и закреплённый исходник llama.cpp.
Не устанавливайте PyTorch, Transformers или CUDA на VPS: приложению они не нужны.
При замене весов остановите сервисы, сохраните прежнюю папку `models/cpu`,
распакуйте и проверьте новый комплект, затем запустите сервисы снова.

Веб-интерфейс слушает только localhost. Для доступа со своего компьютера:

```bash
ssh -L 8000:127.0.0.1:8000 user@VPS_IP
```

Откройте `http://localhost:8000`. Для публичного домена настройте reverse proxy
с TLS и авторизацией; endpoint модели наружу не публикуется.

```bash
docker compose -f compose.cpu.yaml logs --tail 100 model branddeck
docker stats --no-stream
docker compose -f compose.cpu.yaml down
```

Модель и приложение запускаются автоматически после перезагрузки Docker.
Одна копия базы обслуживает текстовый план и выбор макетов: адаптер выключен для
плана и включается только в отдельном запросе выбора. Анализ геометрии и стилей
выполняется по OOXML. Тяжёлые операции приложения идут последовательно.
Лимиты памяти: модель 2304 МиБ, приложение 1152 МиБ; остальное оставлено ОС.
LibreOffice и большие PPTX могут потребовать больше памяти, поэтому обязательно
проверьте свои файлы на VPS. Время генерации на Intel E5 заранее не гарантируется.

Контекст ограничен 4096 токенами. Слишком длинный исходник или неполный ответ
модели фиксируется как причина перехода к детерминированному плану в `deck_plan.json`;
скрытого обрезания исходного текста нет. Сначала проверьте короткую презентацию.
`cpu_report.json` измеряет процесс модели; он не заменяет проверку потребления
всего VPS и качества итогового PPTX. Обучение на A100 и запуск Docker на вашем
сервере выполняются отдельно — наличие кода само по себе не означает их прохождения.

Источники: [llama.cpp server](https://github.com/ggml-org/llama.cpp/tree/master/tools/server),
[конвертер LoRA](https://github.com/ggml-org/llama.cpp/blob/master/convert_lora_to_gguf.py).
