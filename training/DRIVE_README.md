# Папка lct для Google Drive

Загрузите **эту папку целиком** в «Мой диск» Google-аккаунта, где доступна A100.
Должно получиться `Мой диск/lct/data/train.jsonl`, а не `lct/lct/data/train.jsonl`.
Привязывать GitHub не нужно. Базовая модель общедоступна и скачивается автоматически.

1. Войдите в Colab под аккаунтом с A100.
2. Через «Файл → Загрузить блокнот» откройте `BrandDeck_A100_Training_Drive.ipynb`.
3. Выберите GPU A100 в настройках среды.
4. Выполняйте разделы 1–4: проверка файлов, установка, обучение, результаты.
   В конце раздела 4 есть ячейка скачивания архива весов; на этом можно закончить.
5. Разделы 5–7 загружают сохранённые веса и подключают модель к приложению.
6. Ячейку «Остановка» выполняйте после работы, не запускайте весь notebook одной командой.

Окружения обучения и API создаются через uv с Python 3.12 и pip. Версия Python
ядра Colab может отличаться. Это устраняет зависимость от системного ensurepip
при создании venv. Повторный запуск проверяет и интерпретатор, и pip; неполная
установка получает новую локальную папку. Логи установки выводятся в notebook.
Если старый notebook падает на `python -m venv`, замените раздел 2 обновлённой
ячейкой из `BrandDeck_A100_Training_Drive.ipynb`. Перезагрузка данных на Drive не нужна.

```text
lct/
  BrandDeck_A100_Training_Drive.ipynb
  README.md
  templates/                 исходные три PPTX
  data/
    train.jsonl              примеры обучения
    validation.jsonl         отдельный шаблон для проверки
    manifest.json            происхождение, количество, SHA-256
  scripts/
    train_layout.py
    data_utils.py
    checkpoints.py
    requirements-a100.txt
  weights/                   заполняется после обучения
  runs/                      замеры и полные чекпоинты обучения
```

Исходные файлы: `VK Tech шаблон.pptx`, `Шаблон презентации VK Education.pptx`,
`VK_WorkSpace_Клиентская_конференция_Шаблон_03.pptx` из `task+data/Датасет`.
PDF `4. VK Tech.pdf` содержит условия и не используется как обучающий пример.
Упомянутого в условиях отдельного контент-пакета в полученной папке нет.
Для этого эксперимента тексты и признаки макетов уже извлечены в JSONL.
Весь репозиторий, `.git`, окружение Python и ключи на Drive переносить не нужно.

Обучается QLoRA-адаптер **выбора макета**, база — Qwen2.5-7B-Instruct.
Это текстовая модель; для этого профиля `INFERENCE_VISION=0`.
Данные получены из текста и структуры трёх PPTX. Разметка слабая: исходный
макет слайда считается целевым среди кандидатов, хотя другой макет тоже может
подходить. Поэтому точность на этих метках не равна качеству презентаций.
Перестановки кандидатов — аугментация, они не увеличивают число независимых слайдов.

В обучение идут VK Tech и VK Education. VK WorkSpace оставлен для проверки;
совпадающие группы текстов убраны из проверки. Три стиля — маленький эксперимент,
не доказательство переноса на произвольный бренд. Notebook сравнивает адаптер
с базовой моделью и текущими эвристиками, не обещая улучшения.

После успешного обучения:

- `weights/<run_id>/adapter/adapter_model.safetensors` — дополнительные веса;
- `weights/<run_id>/adapter/adapter_config.json` — параметры адаптера;
- `weights/<run_id>/adapter.zip` — архив для скачивания;
- `weights/latest.json` — ссылка на последний завершённый запуск;
- `runs/<run_id>/metrics.json` — сравнение до/после и с эвристиками;
- `runs/<run_id>/run.json` — точная версия базы, GPU, настройки и время.
- `runs/<run_id>/checkpoints/checkpoint-*/` — полные состояния для продолжения;
- `runs/<run_id>/resume_latest.json` — указатель на последний проверенный чекпоинт.

Чекпоинты обязательны: первый после шага 1, затем каждые 10 шагов оптимизатора
и в конце каждой эпохи. Внутри — веса адаптера, токенизатор, `optimizer.pt`,
`scheduler.pt`, `rng_state.pth`, `trainer_state.json`, `training_args.bin`.
SHA-256 и `COMPLETE.json` позволяют исключить незавершённые или повреждённые копии.
На Drive остаются две последние целые копии; старая удаляется только после проверки
новой. Для чекпоинтов и итогового архива оставьте несколько ГБ свободного места.

После обрыва Colab заново выберите A100 и выполните разделы 1–3 с `RESUME='auto'`.
Восстановятся состояние оптимизатора, scheduler, RNG и номер шага. Работа после
последнего сохранения будет повторена. EPOCHS и MAX_LENGTH оставьте прежними.
Завершённый запуск повторно не обучается. `RESUME='none'` создаёт новый запуск,
а `RESUME='<run_id>'` выбирает конкретный. Версия базы берётся из исходного запуска;
изменённые данные, параметры или версии библиотек блокируют несовместимое продолжение.

Адаптер загружается **вместе с базовой моделью той же версии**. Самостоятельно он
не работает. Полную копию базовых весов хранить на Drive не требуется.
Для нового запуска API без повторного обучения: раздел 1, затем разделы 4–7.
На локальном компьютере выбирайте `INFERENCE_MODEL=Qwen/Qwen2.5-7B-Instruct`,
а для адаптера — отдельную переменную `INFERENCE_LAYOUT_MODEL=lct-layout`.

## Перенести веса обратно в проект

Скачайте `lct/weights/<run_id>/adapter.zip` с Drive аккаунта с A100. Архив содержит
весь адаптер и токенизатор, `training_run.json` с точной версией базы, `metrics.json`,
`requirements.freeze.txt`, `dataset_manifest.json` и `SHA256SUMS.json`.
Не переносите только один `.safetensors`: нужен весь комплект.

Распакуйте архив в `lct_vk/models/lct-layout/` (для другого эксперимента выберите
другую папку). В PowerShell из корня проекта:

```powershell
Expand-Archive -LiteralPath 'C:\ПУТЬ-К-СКАЧАННОМУ\adapter.zip' -DestinationPath '.\models\lct-layout'
```

Само наличие файлов не включает их в приложении: оно обращается к inference API.
Простой вариант — разделы 5–7 ноутбука: A100 загружает базу с адаптером из Drive,
а проект на компьютере использует выданный адрес. GitHub-аккаунт для этого не нужен.
Пока используется такой API, Colab должен оставаться запущенным.

Для переноса вычислений на свой GPU-сервер с установленным vLLM, из корня проекта
в Linux/WSL2 (путь адаптера должен быть доступен этому серверу):

```bash
REVISION=$(python -c "import json; print(json.load(open('models/lct-layout/training_run.json'))['base_revision'])")
vllm serve Qwen/Qwen2.5-7B-Instruct --revision "$REVISION" \
  --host 127.0.0.1 --port 8001 --dtype bfloat16 --max-model-len 32768 \
  --max-num-seqs 1 --gpu-memory-utilization 0.85 \
  --enable-lora --max-lora-rank 16 --lora-modules lct-layout=models/lct-layout
```

Настройки проекта для API на том же компьютере:

```powershell
$env:INFERENCE_BASE_URL='http://127.0.0.1:8001/v1'
$env:INFERENCE_MODEL='Qwen/Qwen2.5-7B-Instruct'
$env:INFERENCE_LAYOUT_MODEL='lct-layout'
$env:INFERENCE_VISION='0'
python -m slide_agent serve
```

Для Colab используйте адрес и API-ключ из ноутбука. Не подставляйте `lct-layout`
в `INFERENCE_MODEL`: адаптер выбирает макет, а базовая модель планирует содержание.
Чекпоинты оптимизатора для работы приложения не нужны; оставьте их на Drive.

Механизмы: [Trainer resume](https://huggingface.co/docs/transformers/v4.57.1/en/main_classes/trainer#transformers.Trainer.train),
[формат PEFT](https://huggingface.co/docs/peft/v0.17.0/en/developer_guides/checkpoint),
[vLLM LoRA](https://docs.vllm.ai/en/latest/features/lora/).

Комплект подготовлен и проверен локально; фактическое обучение на A100 ещё
не выполнялось. GPU-совместимость и качество станут известны после запуска.
